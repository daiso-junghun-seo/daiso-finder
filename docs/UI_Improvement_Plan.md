# UI Improvement Plan — 목업 → 프로덕션

> 상태: 제안 (owner 승인 후 컴포넌트 단위로 분할 이행 — 3단계)
> 근거: 2026 트렌드 리서치 + Refactoring UI 원칙 + Bible Interface 계약.
> 계약 불변: 복사 문구 · 6상태 · L1–L4 · 바텀독 · 타이포 매핑 · 색 역할 · 44/8 ·
> 포커스 순서 · 라이브 리전 · 200% 스케일 · D083 · AA(기계검증).

## 1. 리서치 요약

### 1.1 2026 트렌드: Liquid Glass + Adaptive Transparency

- Apple iOS 26의 정의적 언어: 정적 glassmorphism이 아니라 **살아있는 물질** —
  광학 유리 특성(굴절·반사 하이라이트·유동성) + 콘텐츠 적응형 투명도.
- 2026 비판도 동시에 정립됨: 버튼 위장(camouflaged buttons), 아이콘 뭉개짐,
  균질화. 즉 **접근성 우선 구현이 정답** — 이 저장소가 이미 가진 것
  (틴트 보장 ≥4.5 · `prefers-reduced-transparency` 폴백 · 단일 블러 레이어)이
  비판에 대한 올바른 응답이다. 트렌드를 쫓아 투명도를 올리는 것은 금지.
- CSS 구현 범위: `backdrop-filter: blur() saturate()` + inset specular highlight
  + 틴트. **굴절(refraction)은 순수 CSS 불가** (SVG 필터 영역 — 스코프 밖으로 기록).

### 1.2 Refactoring UI 핵심 규칙 (이 플랜에 직접 쓰는 것만)

- **여백**: 너무 넓게 시작해서 좁혀라. 그룹 밖 여백 > 그룹 안 여백. 모바일 퍼스트.
- **계층**: 크기+굵기+색의 조합. 강조보다 **탈강조**(muted는 배경과 같은 hue).
  `h1`을 무조건 크게 하지 마라 — 의미는 태그로, 스타일은 계층으로.
- **레이블**: 형식이 의미를 말하게 하라 (`재고 3개 이하`처럼 값에 녹여라).
- **정렬**: 2–3줄 넘으면 중앙정렬 금지. 숫자는 우측(표) 또는 tabular.
- **타이포**: 헤드라인은 `-0.05em` 타이트하게. 행간은 스캔 난이도 순.
- **색**: 회색에 온기/한기. 원색에서 hue를 살짝 틀어라. 색만으로 구분 금지.
- **깊이**: 보더 대신 그림자. 그림자 5단계 시스템. z축 의도를 그림자로.
- **마무리**: 보더를 줄여라 (그림자·배경색·여백으로). 빈 화면을 비워두지 마라.
- **규율**: grayscale-first — 색 없이 계층이 서야 한다 (이 저장소는 대비-first로 동등 이행 중).

## 2. 레이아웃 구성 및 여백 시스템

### 2.1 스케일 (Tailwind 등가 — 의존성 아님)

Tailwind spacing의 0.25rem 베이스를 이미 쓰고 있다. 의존성 추가 없이 스케일
의미만 공유한다 (프레임워크 도입 기각 사유는 §B36: 토큰·검증·관용 전부 재작성).

| 토큰 | 값 | Tailwind 등가 | 용도 |
|---|---|---|---|
| `--space-xs` | 4px | 1 | 아이콘-텍스트 간격 |
| `--space-sm` | 8px | 2 | 카드 내부 리듬, 행 간격 최소 |
| `--space-md` | 12px | 3 | 행 내부 패딩, 섹션 내 간격 |
| `--space-lg` | 16px | 4 | 화면 거터, 카드 패딩 |
| `--space-xl` | 24px | 6 | 섹션 간격 |
| `--space-2xl` (신규) | 32px | 8 | 히어로 상단 에어, 빈 상태 여백 |

신규 `--space-2xl` 1개만 추가한다. 나머지는 현행 유지 (E2E 기하 고정값과 연동).

### 2.2 그룹 규칙 (신규 문서화 — 코드 변경 아님)

- 그룹 밖(카드↔카드, 섹션↔섹션) ≥ 16px, 그룹 안(카드 내부) ≤ 12px.
- 현재 위반 1건: `.answer-card > div > * + *` 8px는 유지 (카드 내부이므로 정당).
- Default 빈 화면: 헤드라인 상단 에어 `--space-2xl`로 (현재 `--space-xl` + 거터 —
  목업 순서는 유지, 공기만).

## 3. 색상 체계

### 3.1 현행 매핑 (유지)

액션 잉크 / 성공 그린 / 에러 레드 / 중립 — 역할 불변. 빨강 복귀 없음 (§B43).

### 3.2 다듬기 (신규 토큰 2개)

- `--surface-raised`: 카드 내부 섹션 구분이 필요할 때 쓰는 1단 올린 면
  (light `#ffffff`→ 카드가 이미 흰색이므로 **불필요 판정** — 기각 기록.
  다크 `#1c1c1e` 위 `#242428`? 다크 카드가 이미 `#1c1c1e` — 섹션 구분이
  실제로 필요해지면 그때, 지금은 추가 안 함).
- 결론: **신규 색 토큰 없음**. 온기 그라운드는 §B41로 확정됨.
- 대비 검증: 기존 행 전부 재사용 (토큰값 변경 없음 → 테스트 변경 없음).

## 5. 이행 순서 (3단계 — 승인 후 컴포넌트 단위)

- P1: C2 답 카드 (보더→섀도) + C3 후보 행 (보더→섀도) — 시각 변화 최대, 위험 최소
- P2: C1 헤드라인 트래킹 + C7 빈 에어
- P3: 잔여 (C5 기각 확인만 — 코드 없음)
- 각 PR: 해당 컴포넌트 테스트 + 전체 게이트 + 스크린샷(라이트·다크) + 리뷰 → 병합
